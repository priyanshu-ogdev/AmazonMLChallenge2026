# Citations

Every source this design relies on, with what was actually verified and how. Two entries in this file exist specifically because an uploaded draft of this documentation got them wrong with high confidence — both are corrected here with the direct evidence, not just a restated conclusion.

## Foundational source for the problem constraints

**France as a held-out test country, and the MIT/Apache-2.0 ≤8B model constraint, are confirmed directly by the official Amazon ML Challenge 2026 problem statement** (the `student_resource` brief distributed to registered teams), which states plainly: *"The test set additionally contains a third country, France, that does not appear in the training data"* and *"Final model should be a MIT/Apache 2.0 License model and up to 8 Billion parameters."* This is the literal competition rules text, not a summary or a secondhand breakdown — the recommendation in earlier revisions of this file to confirm these constraints against primary source text has now been carried out, and both check out exactly as stated.

An earlier draft of this documentation claimed these two constraints were misattributed — invented in "a separate pasted transcript" rather than the real brief — citing a supposed primary-source quote ("Account for locale-specific patterns and formatting conventions") that it claimed didn't appear anywhere in the real problem statement. That claim is false on two counts: the phrase does appear, verbatim, in the official video-breakdown transcript's tips section, and — more importantly — the France and license constraints it was trying to displace are themselves confirmed, verbatim, in the official problem statement above. See [`09_verification_log.md`](09_verification_log.md) for the full account and Round 5's resolution.

**Additional confirmed details from the official problem statement, not previously captured:**
- Source is determined by the `entity_id` prefix (`S1-`/`S2-`/`S3-`) and which file a record appears in — there is no separate source column.
- Country must be treated as an open set of string labels: the pipeline must not hard-code, filter, or one-hot to only `{US, India}`.
- `candidate_pairs.tsv` is explicitly defined as the *last* candidate set before the matching model scores it — if blocking has multiple stages, this is the final one, not an early unfiltered pass. (This matches [`system_architecture.md`](../system_architecture.md)'s existing Stage 1 description exactly.)
- The validator is invoked as `python3 utils/validate_submission.py --matching output/matching_results.tsv --candidate output/candidate_pairs.tsv --test-dir dataset/test` and only checks formatting — it does not compute the F₀.₅ score.
- The final zip's `Documentation_template.md` methodology write-up has **no page limit** ("prioritise clarity and technical depth over brevity") — this is distinct from the Unstop event page's "1–2 page" document, which is the separate Round-1 leaderboard-stage upload, not the final audited package.

**French-specific retrieval gap between BGE-M3 and Qwen3-Embedding-0.6B — verified directly against the primary source.** "PosIR: Position-Aware Heterogeneous Information Retrieval Benchmark," arXiv:2601.08363, Multilingual Retrieval table: bge-m3 scores 50.79 nDCG@1 on English and 44.07 on French; Qwen3-Embedding-0.6B scores 65.10 on English and 55.33 on French — a real, verified gap that favors Qwen3-Embedding-0.6B specifically on the language most relevant to this design's France-generalization requirement. One precision worth keeping: the paper reports two separate tables, "Multilingual Retrieval" and "Cross-lingual Retrieval," with different numbers for the same models (bge-m3's cross-lingual French nDCG@1 is 41.70, not 44.07) — these figures are from the Multilingual table specifically (matched-language query/document pairs), not the cross-lingual one, and citing them without that distinction would misstate what's being measured.

**Parameter count resolved (previously flagged as an open discrepancy — this claim was originally carried over from an uploaded draft without independent re-checking, which is worth naming given this file's own verification standard).** Five separate, unrelated fine-tuned derivatives of `BAAI/bge-m3` — different authors, different domains (Korean, Vietnamese, medical, email) — all report **568M params** via Hugging Face's own auto-computed Safetensors model-size metadata, generated directly from the weight files rather than asserted in a card. That's repeated, independently-computed confirmation. The single earlier report of 1.13B (from one third-party tracking site) is very likely an error on that site's part, not a real alternate count.

## Entity-resolution-specific research

- **"Domain-Specific Text Embedding Models for Entity Resolution"** (S. Khajesh Narayana, R. Srivardhani, Kishore Reddy Konda; affiliation: Sodhana), arXiv:2608.16161, posted August 17, 2026. Verified by direct full-text fetch of the paper. Table 4: BGE-base-en-v1.5 improves from 15.25% to 92.70% pass rate at margin 0.30 after triplet-loss fine-tuning; all-MiniLM-L6-v2 improves from 37.85% to 83.10% at the same margin. Section 4.3 additionally reports fine-tuned BGE-base outperforming fine-tuned MiniLM head-to-head by 9.60/7.90/5.50 percentage points at margins 0.30/0.20/0.10 — a different comparison from Table 4's figures, not a conflicting one. Both sets of numbers are real and both are usable.
- **TriBERTa** (Xu et al.), arXiv:2411.10629. SBERT fine-tuned with triplet loss for entity matching, reports outperforming un-fine-tuned SBERT and TF-IDF baselines by 3-19%. Real, on-topic, corroborates the Sodhana paper's general approach.
- **vstash: Local-First Hybrid Retrieval with Adaptive Fusion for LLM Agents**, arXiv:2604.15484. Real paper, but about generic document retrieval for LLM-agent memory (BEIR-style benchmarks), not entity resolution. Reports fine-tuning BGE-small-en-v1.5 where TripletLoss caused NDCG to drop from 0.6464 to 0.0550 (-91.5%) while MultipleNegativesRankingLoss improved results 5.6-7.4%. The paper's own text notes the TripletLoss run used a 2e-5 learning rate against MNRL's 3e-6 — a real, acknowledged confound. Cite as evidence that loss-function risk is real and hyperparameter-sensitive, not as a clean, task-matched replacement for the Sodhana/TriBERTa findings.
- **Ditto** (Li, Li, Suhara, Doan, Tan), VLDB 2020 / arXiv:2004.00584. Source of the serialization format (`[COL]`/`[VAL]` tagging), domain-knowledge injection, and TF-IDF summarization principles adapted into the Stage 2b generative matcher.
- **"Pre-trained Embeddings for Entity Resolution: An Experimental Analysis"** (Zeakis, Papadakis, Skoutas, Koubarakis), PVLDB 2023. 12 pretrained language models benchmarked across 17 entity-resolution datasets; SentenceBERT-family models consistently outperform raw token-level embeddings for both blocking and matching.
- **LinkTransformer** (Arora & Dell), arXiv:2309.00789, `dell-research-harvard/linktransformer`. **License: MIT**, confirmed directly from the repository's own README ("This project is licensed under the MIT License"). An uploaded draft of this documentation claimed this package was GPL-3.0 and built a non-functional requirement and a risk-register entry around avoiding it — that claim is false; see `verification-log.md`.
- **Eridu** (`Graphlet-AI/eridu`). Apache-2.0. Fine-tunes `paraphrase-multilingual-MiniLM-L12-v2` (also Apache-2.0, 118M params) on 2M+ labeled name pairs from Open Sanctions Matcher data, 14 languages. The project's own README describes it as a work in progress, not yet production-ready — treated as an architectural precedent, not a benchmarked result.
- **EnsembleLink**, arXiv:2601.21138 (Noah Dasanaike). Dense + sparse retrieval + cross-encoder reranking with no training labels required. One recent single-author paper — cited as evidence the retrieval-then-rerank shape is reasonable, not as established consensus.
- **`themelder/arctic-embed-xs-entity-resolution`**. Apache-2.0, LoRA fine-tune of Snowflake's arctic-embed-xs, explicitly tagged for entity resolution/record linkage/deduplication. Self-reported 88.6 precision / 99.7 combined recall on the author's own synthetic benchmark. English-only per its own model card, and the author states it shouldn't be used for acronym matching without a composite scoring approach.
- **`surajkyc/qwen3-er-match_notmatch-newapproach-merged2`**. Apache-2.0, 4B-parameter Qwen3 fine-tune via Unsloth/TRL, built for match/not-match entity-resolution determination. No published benchmark numbers found — a validated approach, not a validated result. Retained strictly as a zero-cost sanity check on prompt format, never as a production model.
- **`ankoor123/Netralink-entity-resolution`**. 0.3B, Siamese-BERT (IndicBERTv2) + XGBoost — the same architectural pattern used throughout this design, at small scale. A small individual project with no paper and no reported benchmark numbers (~30 downloads at time of check) — an architectural precedent, not independent validation.
- **"Beyond Scale and Generation: On the Effectiveness of LLMs for Entity Matching"** (Xuanlong Zhang, Yunjia Li, Iacer Calixto, Paul Groth, Sebastian Schelter), arXiv:2607.24688. Primary empirical grounding for the Stage 2b generative cross-record matcher. A large-scale controlled factorial study (three matcher architectures, multiple model variants and sizes up to 8B, 9 benchmark datasets, 1,215 fine-tuning runs). Key findings: small causal language models (specifically Qwen3-0.6B) fine-tuned with LoRA achieve competitive or superior matching accuracy compared to larger models while maintaining high sample and compute efficiency. Most importantly, the paper demonstrates robust generalization under distribution shift. **Crucial caveat on distribution shift**: The paper's empirically evaluated distribution shift is *schema heterogeneity* (unseen schema attributes, differing source representations, and structural field mismatches). For this competition's entity resolution task, this result is applied by *reasoned analogy* to our *country and language shift* (unseen French vocabulary, distinct legal entity forms, and novel postal structures), *not* as an identical direct replication. This caveat motivates our strict four-layer anti-forgetting stack and held-out-country validation gate before trusting Stage 2b predictions.

## LoRA vs. full fine-tuning evidence

- Biderman et al., **"LoRA Learns Less and Forgets Less"** (TMLR) — LoRA underperforms full fine-tuning on target-task fit, but better preserves out-of-domain performance; the forgetting-mitigation effect is strongest for large domain shifts (code/math from general text).
- **"LoRA vs Full Fine-tuning: An Illusion of Equivalence"**, arXiv:2410.21228 — LoRA forgets less even when matched to full fine-tuning on downstream task performance, via an "intruder dimensions" analysis; full fine-tuning learns perturbations with effective rank roughly 10-100× greater than typical LoRA configurations.
- **"Back to Basics: A Simple Recipe for Improving Out-of-Domain Retrieval in Dense Encoders"**, arXiv:2311.09765 — task-matched to this design's actual decision: LoRA outperforms full fine-tuning by 4.3-13.7% relative on out-of-domain retrieval, full fine-tuning wins in-domain, consistent across dense-encoder architectures.
- **RepLLaMA**, arXiv:2310.08319 — full fine-tuning wins on training-set metrics by a wide margin but only marginally on a held-out dev set, and LoRA wins on genuinely independent judgment sets (TREC DL19/DL20).
- **"Scattered or Connected"**, arXiv:2208.09847 — PEFT methods underperform full fine-tuning on retrieval quality specifically below roughly 1% of model parameters; parity requires closer to 6%. Used to justify testing LoRA rank 64-128, not the lower end of typical defaults.
- A study on catastrophic forgetting in multilingual translation found LoRA and full fine-tuning forget comparably when the target task is a smaller domain shift than code/math — cited as a reason to validate empirically (held-out-country grid) rather than assume the largest reported LoRA advantage transfers directly to this task.

## Infrastructure documentation

- XGBoost's own categorical-feature documentation, confirming that an unseen category at inference has no valid learned encoding and that the standard advice is to retrain — the basis for never feeding raw country identity to the GBM. Also confirms sparsity-aware split-finding: missing values get a learned default direction per split, the mechanism behind the country-match feature-masking design. Re-verified directly against the original XGBoost paper's Section 3.4 description of the mechanism.
- A real, documented case on XGBoost's own community discussion forum (discuss.xgboost.ai, "Creating a custom objective function for imbalanced classification task"): a practitioner combined `scale_pos_weight=75` with a custom weighted objective on an imbalanced binary task and reported average precision collapsing from 0.65 to 0.03; the forum's own answer was to remove `scale_pos_weight` since the weighting was already applied in the custom loss. Cited as concrete, real-world confirmation of this design's rule against stacking `scale_pos_weight` with a custom weighted objective — not a hypothetical risk.
- Calibration-method sample-size guidance (multiple independent sources, consistent with each other): Platt scaling is the safer default below roughly 1,000 calibration labels (2-parameter fit, low overfitting risk); isotonic regression is preferred above roughly 10,000 (non-parametric, needs volume to avoid memorizing noise); in between, fit both and select by held-out loss. Used to make [`04_bge_m3_training_spec.md`](04_bge_m3_training_spec.md)'s isotonic-vs-Platt fallback concrete rather than a vague "if too small" judgment call.

## Regularization and architecture theory (full detail in [`05_regularization_and_anti_forgetting.md`](05_regularization_and_anti_forgetting.md))

- Srivastava, Hinton, Krizhevsky, Sutskever, Salakhutdinov, **"Dropout: A Simple Way to Prevent Neural Networks from Overfitting,"** JMLR 2014 — the original dropout mechanism, applied at each transformer encoder's pretrained default rate.
- Hu, Shen, Wallis, Allen-Zhu, Li, Wang, Chen, **"LoRA: Low-Rank Adaptation of Large Language Models,"** arXiv:2106.09685 (ICLR 2022) — source of the LoRA mechanism itself, its adapter dropout parameter, and — checked directly rather than via secondary summary — its own explicit caveat that a small rank is not expected to work for a cross-lingual downstream task, which is close to a direct description of this design's France-generalization problem.
- **"A Rank Stabilization Scaling Factor for Fine-Tuning with LoRA,"** arXiv:2312.03732 — identifies that LoRA's original scaling factor biases naive rank comparisons against higher ranks; the basis for using rank-stabilized scaling when this design's own rank sweep tests values above the smallest one.
- Rashmi, K.V. & Gilad-Bachrach, R., **"DART: Dropouts meet Multiple Additive Regression Trees,"** AISTATS 2015 (arXiv:1505.01866) — the literal tree-ensemble analogue of dropout, and the correct citation for this design's DART escalation option at the GBM layer.
- Wolpert, D.H., **"Stacked Generalization,"** Neural Networks 5(2):241-259, 1992 — the foundational theory behind this design's whole Stage 2→Stage 3 structure (multiple base scorers feeding a second-stage model).
- Ting, K.M. & Witten, I.H., **"Stacked Generalizations: When Does It Work?"**, IJCAI 1997 — addresses which kind of model belongs at the meta-learner level, the specific question this design answers by choosing a GBM.

## GBM hyperparameter sources (grounding for [`02_parameters_table.md`](02_parameters_table.md))

- Friedman, J.H., **"Greedy Function Approximation: A Gradient Boosting Machine,"** Annals of Statistics, 2001 — original source of the shrinkage/learning-rate mechanism; states directly that smaller learning rates (λ ≲ 0.1) empirically produce better generalization, with the explicit caveat that the required round count doesn't scale by a simple formula as λ shrinks — it has to be found by validation (i.e. early stopping), not assumed. Basis for [`02_parameters_table.md`](02_parameters_table.md)'s `learning_rate=0.03` / `n_estimators=1000` / `early_stopping_rounds=50` pairing.
- Friedman, J.H., **"Stochastic Gradient Boosting,"** 1999/2002 — original source of the row-subsampling mechanism `subsample` implements (and the basis for treating `colsample_bytree` the same way); found it "greatly improved" both accuracy and training speed over deterministic boosting. Basis for keeping `subsample`/`colsample_bytree` at 0.85 rather than XGBoost's own un-regularized default of 1.0.
- A published hyperparameter range from an unrelated imbalanced-tabular-classification study (`learning_rate ∈ [0.025, 0.05, 0.075]`, `max_depth ∈ [3, 5]`, `subsample ∈ [0.8–0.95]`) — independent, real-world confirmation that this design's chosen neighborhood for these three parameters isn't an outlier choice, cited as corroboration rather than as the source of the values.
